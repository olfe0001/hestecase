# Stald API

Express (JavaScript ES modules) and PostgreSQL. The root Docker Compose stack runs PostgreSQL and this API, which also serves the compiled React client. The schema is installed on startup, and demo records are inserted only if no riding schools exist. Restarting preserves profiles, wishes, approved distributions, decisions and the append-only audit log.

Demo login deliberately chooses a profile without a password. Sessions use a random opaque token in an HttpOnly, SameSite=Lax cookie, backed by PostgreSQL and expire after seven days. This is a demonstration identity flow, not production authentication. A future identity provider should resolve to the existing profile and school IDs. Configure COOKIE_SECURE=true when serving through HTTPS.

Entities separate schools, profiles, student details, horses, needs, activity permissions, groups, memberships, lessons, current monthly wishes, closed monthly wish history, distributions, decisions, assignments, audit events and sessions. Repeating needs, memberships and wishes use link tables. Stored information depends on the table's key; UI projections are computed. Horse provenance and synthetic-field labels are metadata JSON, not the application's wish or membership storage.

All access follows the session's school. Teachers read only their own groups and pupils, alongside all school horses. Students read their own private needs, wishes and assignments. Their group roster contains only their own ID. Horse registration and edits require the teacher role. Multi-school growth uses schools and foreign keys; records do not copy school names into child tables. Group teacher references enforce school membership, and database triggers enforce student/group/horse school consistency for memberships, wishes, monthly history, decisions and assignments.

Assignments are checked for student level, weight, horse status, required activity, rest day, daily maximum three lessons, weekly maximum one jumping lesson, simultaneous usage and source constraints. Arthur cannot serve an advanced group; Aida requires a recorded teacher safety assessment; nervous pupils cannot use fear-sensitive horses. A teacher decision cannot override structural safety limits. Hard unknown source weight limits are replaced only in demo seed by explicit synthetic per-horse limits and flagged in syntheticFields: these figures must be reviewed before any real use.

Wishes are unranked. Consecutive closed months of unfulfilled wishes decide priority. Fulfillment or a missing wish interrupts the streak. New pupils have no prior wait. Missing histories require a reasoned teacher decision, as do equal priorities. The fixed demonstration month is October 2026. A session approval does not silently alter monthly history. A production month-close process must archive each month's wishes and fulfillment after the school's complete monthly schedule is decided. Without that process, this POC does not claim ongoing month-to-month operation.

Mutations serialize on the school row, and distributions use a revision. Wish/horse changes invalidate revisions and return current distributions to draft, so pupils never see an obsolete approval after an illness or changed wishes. Approval atomically rechecks persisted assignments against current data and appends an audit entry. Every proposal, edit and approval also stores an immutable before/after snapshot in distribution_versions, preserving previous approved allocations. An optional operationId makes approval retries idempotent. Lesson intervals use a stored duration (45 minutes for demo groups), so overlapping start times are checked as intervals, and each horse retains at least one day without lessons in the week. If another teacher changes a draft, the API returns 409 rather than overwriting. Validation errors return 422 with conflicts. School-wide data changes invalidate the prior revision even when a distribution was approved; a repeat approval always revalidates. Approval requires every displayed priority tie or missing-history conflict to have a recorded teacher decision, including conflicts on a horse not yet assigned in the partial proposal.

Manual acceptance: login as Ellen Frellsen, save three wishes; log in as Anne, generate a Friday group's proposal, resolve the Toobi tie with a reasoned decision, assign every pupil and approve; restart the application and inspect persisted assignments and history. Change a horse to unavailable and confirm a fresh approval fails. Attempt teacher endpoints from an Ellen Frellsen session and confirm 403. Confirm Ellen Frellsen cannot see another pupil's needs or wish history.

Case import subsequently adds all 34 pupil names and the four Friday groups, preserving existing internal IDs. Individual measurements, wishes, needs and history remain demo values. Students can update their own functional needs through PUT /api/profile/needs; only their groups return to draft. Three shared illustrative mockup photos use per-horse image_path/image_kind references. See the feature spec and docs/process.md for the final scope and iteration history.
